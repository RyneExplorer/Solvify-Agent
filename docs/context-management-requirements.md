# 上下文管理迭代需求

日期：2026-10-12。状态：P0—P3 实现及 P4 观测/离线评估入口已交付；真实模型效果调优由用户后续验收。
配套文档：[上下文管理迭代计划](context-management-plan.md)。

## 1. 目标与范围

让快速检索保留必要对话，让深度任务在多次委派、工具调用和中断恢复后仍能可靠继续；每次模型调用遵守统一预算，压缩不改变审批与已执行操作的事实。

核心原则：共用预算和会话素材，分别管理快速运行、深度运行与专业子任务的状态，按角色选择输入。

覆盖会话装配、历史召回、模型调用保护、工具轨迹、任务结果、原文存储、摘要与 checkpoint。沿用现有路由、请求 DTO 和 SSE 契约；公开契约变化须独立评估。不建设通用 Context Engine，不重复建设召回，不仅为模式命名拆出两个 ContextService。

## 2. 改动前基线

- ContextService 已有近期消息、关键词/向量召回、会话摘要、画像、偏好与记忆，History/RecallHistory 已分区。
- 快速已有 budgetGuard Handler；深度入口已有 budgetModel，支持 Generate/Stream/WithTools 和专业任务结果压缩。
- 工具定义占满 Service 安全额度时已返回零，但 BuildContext 会将零回填为默认正数。
- 超限仍只记录日志并放行；输出预留与客户端实际上限不同源。
- 向量候选反转、去重后时间排序、遇到超长项停止选择仍影响相关事实入选。
- Replanner 同时携带 Results/ExecutedSteps；深度已保存 Request 等状态，应核对覆盖范围后补充版本一致性。

上述描述实施前代码，不代表当前缺口全部仍存在。实施结果、证据与未覆盖项见 [迭代记录](../tasks/context-iteration-report.md)。

基线补充：budgetModel 调用 budgetGuard，二者是不同接入职责，并非两套独立预算算法。深度指令已通过最终 system 消息进入 messagesTokens；空 instruction 只表示没有额外补计，不能据此判定漏算指令。工具吃满时当前返回值为 (0,0,0)。

## 3. 功能需求与验收

### R01 统一预算与最终保护

所有纳入迭代的模型调用使用同源预算规则：快速、深度控制角色、专业 Agent、遗留恢复、会话/运行摘要与记忆提取。摘要和记忆调用采用独立限额，不经过递归运行摘要流程。

检查实际消息、实际工具定义及实际生效输出上限。超过硬预算，有限压缩后仍不足必须返回业务错误，底层模型零调用；注册信息仍无法确定窗口时返回配置错误。软水位用于提前压缩，不等同于硬上限。计数为估算，供应商超窗错误仍需分类与窗口收敛。

验收：Generate/Stream/WithTools、调用级选项覆盖、长指令/问题、工具参数、未知窗口；超硬预算零调用，超软但硬预算内可调用。

产品语义：先减少可选素材并重新计数，预算内尽力回答；必要内容仍超硬预算才拒绝。降级与最终拒绝是顺序步骤，不是互斥方案。上线前明确待决策项：哪些素材可删除、减少上下文是否提示用户、失败提示及下一步操作。不得把当前放行描述为保证获得回答，也不得把超软水位等同于超过供应商窗口。

### R02 共享会话素材与正确召回

保留一个 ContextService。近期对话保序，相关历史先按排名选择，再按时间组织。跨容器按 ID 去重、剔除本轮问题，包装及补充问答语境计入预算；超长项不能阻止后续短项入选。

显式零额度表示禁用，未配置才用默认值。关键词排名按真实实现描述。可选召回失败可降级，权限和必要状态读取失败不得伪装成空内容。

候选相关度选择与时间展示分别保持全序：前者使用排名/距离及 ID 裁决并列，后者使用时间及 ID；不能为了时间全序而在选取前丢掉相关度。

验收：旧事实、时间较新但更相关、指代、超长首项、重复、零额度与降级；选中召回进入实际模型输入。

### R03 快速检索独立运行状态

保存当前问题、必要会话素材和自己的工具轨迹；优先减少可选旧召回及可恢复旧结果。短请求不增加同步摘要调用；快速超过软水位时对旧完整问答/工具组生成有限运行摘要，深度模式对旧完整工具组生成有限运行摘要。保留约束、活动调用和澄清状态，不静默截断当前问题。

验收：短请求不新增同步摘要；检索→澄清→跨 Engine 恢复→再检索→回答链路有效，工具配对合法。

### R04 深度角色及子任务隔离

每个任务按 runID/agentID/taskID 隔离状态，不共享可变消息与摘要。每次模型调用单独计算额度，累计任务费用/轮数约束不能代替窗口保护。

- Planner：目标、约束、必要历史与真实可用能力。
- Executor：当前批次、依赖及可信执行状态。
- 专业 Agent：任务、必要依赖结果、授权工具及自身轨迹。
- Replanner：计划版本、任务状态、有限结果、失败/拒绝与剩余任务。
- synthesis_review：必要成功结论及证据，保持现有操作权限边界。

验收：并行隔离，无关轨迹不进入输入；Results/ExecutedSteps 不重复携带大段正文；依赖、终态和汇总覆盖校验保持有效。

### R05 完整组与有限压缩

assistant 的全部 tool_calls 和对应结果属于一个完整交互组。活动调用、审批与必要结构化状态不得淘汰；旧的已完成组才可摘要/移除。

压缩构造新状态，核对版本后一次发布，不原地修改框架/追踪正在读取的对象。每步必须减少或终止，有明确执行上界；摘要失败保留旧状态，仍超硬预算则失败。

验收：多工具配对、活动组保留、无进展终止、并发及追踪回调无竞态。

### R06 工具原文可恢复存储

大结果先保存原文，再替换为关键字段、来源、artifactID 和读取说明。保存失败保留原文；引用不代表模型已掌握原文。

原文以不可变产物为唯一权威来源；消息关键字段与摘要是带版本/哈希的派生展示，不反向改写原文。审批、操作是否执行及任务终态以结构化执行记录为准，产物正文和摘要不能覆盖这些事实。用户后续授权完成全计划，R06 已纳入本轮，按 P2 独立阶段交付数据库、读取工具、配额及清理。

读取按产物 ID 与有上限范围进行，检查当前用户/会话/运行权限，不接受任意文件路径。读取输出计入预算，避免整份回读反复外置。限额、清理与 checkpoint 生命周期协调。

验收：大结果、分段读、越权、写失败、配额/过期和跨实例恢复；有效 checkpoint 不引用已被提前清理的必要内容。

### R07 会话摘要与运行摘要分工

会话摘要继续后台总结已落库对话，服务下一次请求；运行摘要属于运行/子任务及 checkpoint，不覆盖 chat_summaries。

运行摘要保留目标、约束、发现、证据、失败与待办，记录源范围/哈希，仅实际总结的完整组可标为覆盖。独立模型调用有输入预算、输出上限、超时及有限重试，不挂业务工具。

审批、任务终态和副作用事实由结构化状态决定。后台会话摘要/记忆不承担运行防超窗责任。

验收：部分覆盖、重复生成、超时/失败；摘要不得改变拒绝和已执行状态。

### R08 运行版本与恢复一致性

冻结本次会话素材及工具配置标识，记录模型和预算策略。恢复沿用原素材，重新检查当前权限；模型/窗口变化先重新校验，不能无说明混入新素材或切换模型。

checkpoint、运行摘要与产物引用一致发布。版本/哈希不匹配先校验与重建，必要源丢失明确失败。继续使用 ResumeParams 承载审批/澄清。旧 checkpoint 选择安全兼容或明确拒绝，不自动重跑副作用。

验收：快速/深度跨实例恢复、摘要更新、权限撤销、模型变化、多次中断、旧版本/源丢失；批准只执行一次，拒绝不被绕过。

### R09 观测与实测

记录请求/运行/角色、窗口、输出上限、估算口径、软硬预算、来源占用、压缩前后变化、耗时、版本和拒绝原因。复用日志/追踪，中文日志不记录原文、密钥或完整参数。

同一批样本对比事实回答、指代、引用完整性、长任务完成率、首段/总耗时、模型调用数和 usage。记录配置、样本量与局限；量化目标在基线测量后确定，不承诺未经实测的收益。

在预算算法或输入选择变化前先保存基线，记录 HEAD、工作区差异、模型配置、样本版本和计数口径；改动后以同样本复测。持久化探针提前验证摘要、引用及版本哈希；新 Engine 恢复与独立进程恢复分别报告，不互相替代。

## 4. 交付标准

首批交付预算、召回、模式输入边界与基础观测，允许必要内容过大时明确失败。后续交付可恢复原文、完整组压缩、摘要与版本一致性。

当前授权范围为全计划实现。P2/P3 纳入本轮，P4 完成观测与固定样本离线入口；用户要求暂停真实模型/产品验收，因此实际质量、usage、完成率和生产时延仍由后续验收确认，不以工程测试代替效果结论。

全部完成需证明：所有纳入路径受保护、协议合法、任务隔离、原文按权限可恢复、checkpoint 同版本、审批/副作用稳定，并有真实质量与性能对比。文档与已有测试通过不等同于新需求完成。
