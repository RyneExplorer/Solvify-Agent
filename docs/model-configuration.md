# 模型配置契约与升级说明

本轮把系统模型和用户模型统一到同一套能力配置。连接信息保留原有 provider/API format、base URL、模型 ID、API Key；总窗口保留 `max_context_length` 字段，其他能力复用既有 `config` JSONB。当前调用协议仅为 OpenAI 兼容 API，输入仅支持文本。

## 运行前必须确认的能力与调用额度

- `max_context_length`：服务商对当前具体模型或部署声明的总上下文窗口。
- `config.max_input_tokens`：可选的独立输入上限，仅服务商有额外输入限制时填写；缺失或0表示使用共享总窗口，不表示零输入预算。
- `config.max_output_tokens`：模型最大生成额度。
- `config.max_completion_tokens`：该配置实际请求的生成额度；名字表示内部统一额度，发送时按下一个字段选定的协议映射。
- `config.output_token_field`：`max_tokens` 或 `max_completion_tokens`。按服务商文档选择，不能据字段名假定额度一定包含或排除思考 token。
- `config.tool_calling`：是否支持工具调用。明确支持才能执行快速/深度 Agent；配置入口拒绝明确不支持工具的模型，未知能力须在表单补齐并通过服务端实测后保存。
- `config.reasoning_capability`：`none`、`optional`、`always`。
- `config.reasoning_mode`：`default`、`off`、`on`。无思考能力不能开启，始终思考不能关闭。

不自动填入 8192 窗口、4096 输出，也不按模型名或供应商品牌猜测。实际输出必须为正，不超过最大生成额度，且小于总窗口。最大输入、最大生成分别不能超过总窗口；二者是能力上限，不要求它们的和小于窗口。

## 可选参数

- 可切换思考模式需要明确服务商参数协议：`thinking`（发送 `thinking.type`）或 `enable_thinking`。`default` 不额外发送开关。
- 使用 `reasoning_effort` 协议时可选 `low`、`medium`、`high` 强度；开关使用 `default`。这里不假定各服务商存在相同的关闭枚举。
- 思考模式可能开启且需要工具时，必须确认 `tools_with_reasoning=true`；否则先关闭可切换的思考，或选择适合工具的模型。
- `temperature` 可留空，不给不支持温度的模型强加值；填写时为 0–2。
- `timeout` 为可选请求时限（1–300 秒）；仍受 Agent 总执行时限和请求取消保护。

快速/深度是 Agent 编排策略，模型思考开关是供应商调用参数，分别生效。没有新增图片上传、多模态预算或 Anthropic 原生协议。

## 预算与摘要

独立输入上限存在时，有效输入硬预算为 `min(独立输入上限, 总窗口 - 实际输出预留 - 安全裕量)`；否则为 `总窗口 - 实际输出预留 - 安全裕量`。安全裕量、软水位和摘要策略是应用治理策略，不能作为厂商模型能力默认值。

独立输入上限同时用于候选上下文装配、运行摘要、裁剪和最终 HTTP 请求保护。高水位先摘要或减少可选内容；当前问题、必要指令与完整工具调用关系仍超限时才明确拒绝。摘要输出受模型配置实际生成额度约束，不能借摘要调用突破模型限制。

删除了供应商超长错误后把窗口直接降为 8192 的运行时规则。错误不提供可信额度，不能据此修改配置或为后续请求建立猜测窗口。

恢复时校验总窗口、输入限制和输出额度。旧有效快照缺少独立输入字段时，采用当前已确认的输入限制继续保护；不改写旧模型窗口。

## 能力测试与元数据探测

系统和用户入口共用测试实现，保留既有 HTTP 状态和业务码约定，测试结果增加连接、流式和工具状态。

1. 有界读取服务商 `/models` 元数据。只展示含义明确的 `context_window`、`max_input_tokens`、`max_output_tokens`，`max_tokens` 不当作上下文窗口。
2. 数值未确认时只展示元数据建议，不创建模型客户端、不自动保存数值。
3. 完整配置执行合成文本连接测试和流式测试。
4. 声明支持工具时，测试流式模拟 echo 工具调用、参数解析、tool response 与后续回答。没有业务工具、联网检索或文件写入副作用。

`passed` 表示本次当前配置验证成功；`failed` 表示此次测试失败，可能是网络、鉴权、协议或模型行为原因，不能据此证明模型永久不支持某能力。`unknown` 表示未验证，`not_requested` 表示未声明工具支持因而未测试。

元数据来源标记为 `provider_metadata`，只作用户确认依据，不证明最大窗口可用。测试结果不作为持久化的“已认证能力”。真实 DeepSeek 最大窗口、思考与工具兼容性仍需结合所用服务商和具体模型资料、真实调用验证。

## 已有配置升级

新库使用 `scripts/init_knowledge_schema.sql`，模型窗口列没有默认值。已有库在确认 schema 与备份后执行 [20261013_model_limits.sql](../scripts/migrations/20261013_model_limits.sql)。该脚本只删除两个窗口列的默认值，可重复执行，不改已有窗口或 JSON 配置。

部署前逐个补齐启用的系统模型及正在使用的用户配置。旧记录可以继续列出、编辑和删除，表单显示“能力待确认”；缺少能力字段的配置不进入模型调用，并给出模型设置提示。不能直接把历史 8192 当作已确认能力，也不能批量回填猜测的 DeepSeek 额度。非界面 API 客户端创建或更新配置时也必须使用新契约。保存要求能力完整，并自动以候选配置验证真实工具调用；能力未知或验证未通过不写入。运行时仍严格要求能力完整。响应 `capability_status` 由配置即时派生：`pending`（待确认）、`text_only`（旧记录不支持当前工具配置，需更换模型或修正思考设置；不允许新建或保存此类配置）、`ready`。没有新增数据库状态列。

编辑留空保留原密钥。通用列表和系统公开详情保持脱敏；本人模型详情和管理员专用 `/api/v1/models/:id/edit` 返回真实密钥，编辑表单按需加载回填，因此测试和获取能力无需重填。编辑输入框提供小眼睛，切换原文显示/隐藏；切换仅改变显示方式，不修改密钥或测试参数。含密钥详情响应设置 `Cache-Control: no-store`。管理员编辑接口受 RequireAdmin 保护，本人详情沿既有 userID 归属查询；不会把脱敏列表值发送给服务商。

## 验证入口

- 后端：`go test -vet=off -p 1 ./...`，另行 `go vet -p 1 ./...`，Agent/LLM/Service 相关 race。
- 前端：在 `design/vue` 运行 `node --test tests/*.test.mjs` 与 `node node_modules/vite/bin/vite.js build`（等价于现有 npm 脚本）。
- PostgreSQL：设置 `SOLVIFY_MODEL_CONFIG_DB_TEST=1` 后运行 `go test -vet=off -p 1 ./scripts/migrations -run TestModelLimitsMigrationPostgres -v`，所有写入限定在随机创建的临时 schema，验证重复升级、旧记录保留和缺省写入拒绝。

普通测试使用本地模拟 HTTP 服务，无真实模型或业务副作用调用。构建通过不代表真实模型效果已验收。

## 中转站未提供能力数据时

不能把 10K 当作未知模型的默认窗口。即使底层模型同名，中转站也可能限制输入长度或输出额度，不能直接复制其他服务商的能力。

优先使用该部署明确返回的元数据，其次使用该服务商当前文档或用户确认的额度。两者均没有时保留“能力待确认”；若用户自行指定保守额度用于实验，应将其作为临时运行限制并另行记录来源，不能称为厂商能力认证。当前不会自动为未知模型启用 10K 限制。总窗口与实际输出必须一起确认；独立输入限制仅在部署明确要求时填写，否则小窗口配大输出会再次压缩可用输入空间。

元数据探测失败、空目录或没有能力字段，不能证明模型已下架或不支持工具；短请求成功也不能证明最大窗口。能力测试采用合成短请求，不通过不断增大真实请求去穷举模型窗口。

## 新增工具与窗口

窗口来自本次模型配置，新增工具不更换窗口，也不重置输入/输出额度。实际工具定义计入每次最终请求的输入预算，超限先减少可选上下文，仍超限才拒绝。工具绑定与调用级工具覆盖均受相同保护。

深度 Planner 根据当前权限允许的知识、外部与文档工具描述生成计划；新增知识工具的名称与用途也进入 Planner 输入。恢复时重新取得允许的工具集，删除或被权限过滤的工具不残留在新描述中。明确需要工具取得的事实不能直接安排无工具的汇总。

2026-10-13 本地数据库经授权更新了两个官方 DeepSeek 配置与 GLM-4.7-Flash 配置，删除两列旧默认。DeepSeek 官方元数据返回总窗口 1,048,576、最大生成 393,216；GLM 官方说明为 200K/128K，本地配置使用 200,000/128,000。三者实际调用生成额度单独配置为 8192，并关闭可切换思考。其余缺少可信额度的中转站配置未猜测回填。更新前能力字段备份位于本地 `tasks/model-config-db-backup-20261013-184354.json`，不包含 API Key。

真实测试：两个 DeepSeek 均通过运行中 API 的连接、流式和模拟工具验证；快速/深度 Agent 使用新增内存工具的同一样本也通过。GLM 曾返回 HTTP 429/厂商码1305，后续连接成功但流式与工具未稳定通过；不计作完整验收。没有用这些短样本证明最大窗口或开启思考后的行为。

## 获取能力与保存门禁（2026-10-14）

表单分别提供“获取模型能力并回填”和“测试连接 / 流式 / 工具”。复用系统 `/api/v1/models/test` 和用户 `/api/v1/user/model-configs/test`，新增 `operation=capabilities` 为只读能力获取；`test` 或省略仍走原测试流程。权限、HTTP状态和业务码沿用现有入口。获取不调用聊天模型、不保存数据库、不自动选择实际输出额度或思考开关。

获取优先使用当前部署 `/models` 明确返回的能力额度，不混合不同来源的额度。未返回明确额度时，仅对核实过的官方HTTPS主机、路径及模型ID查询内置资料目录；目前限官方DeepSeek的deepseek-flash/deepseek-v4-pro与官方GLM-4.7-Flash，资料核对日期为2026-10-13。目录维护在 `internal/service/model_capabilities.go`，资料URL和日期与数据一起维护；中转站、非标准路径或同名其他模型不匹配。元数据和目录都缺失时无默认10K/32K，用户在表单中查阅该部署资料后手填，完整后才能验证并保存。

点击获取会显式回填返回的字段，失败保留已有手填值。成功时展示资料出处和核对日期；保留实际输出额度，不替用户选择。`config.capability_origin` 保存出处（source/url/checked_at），仅作为资料记录，不是服务商认证，也不是授权依据；手动改参数时标为手动确认。没有能力数据的字段仍需用户确认。客户端请求期间更换部署身份，旧获取结果不再回填。

更换协议、模型ID或base URL会清空表单旧能力。服务端也会使旧窗口和能力失效；API客户端若在一次更新中重新确认，需显式传 `reconfirm_capabilities=true`，并同时提交完整 `config` 和 `max_context_length`，服务端严格检查后保留新能力；否则本次更新被拒绝，旧记录保持不变。前端保存已补齐的新能力时提交此确认标记。未修改部署身份时不需要确认标记，保存仍必须通过工具实测。

本轮未更改生产模型额度，也不为三条未知部署记录猜数。已有数据库列支持窗口0和JSONB草稿，无新增schema。服务需重启加载后端改动；真实服务商测试依旧受凭据、网络与配额约束，离线通过不代表所有代理能力已确认。


## 工具准入与紧凑表单（2026-10-13）

项目聊天需要工具调用，系统/用户创建、更新入口都拒绝 `tool_calling=false`；思考可能开启且明确 `tools_with_reasoning=false` 时同样拒绝，应关闭可切换思考或更换模型。能力未知时不能保存为新可用配置；历史待确认记录可以查看、删除或补齐后重新验证保存。底层LLM内部摘要仍允许不携带工具，不扩大为产品纯文本模型配置入口。现有不支持工具的记录不自动删除，编辑时提示修正，运行保护继续有效。

表单默认显示窗口、输出额度、工具及思考能力，采用响应式网格；独立输入上限、思考协议、温度和超时放在高级折叠区。能力来源缩为短标签，资料详情在折叠区；弹窗限制高度并允许滚动，按钮可换行。


## 保存前工具实测（2026-10-14）

`tool_calling=true` 只是静态声明，不能作为能力证据。创建与更新模型由Service自动用候选地址、模型ID、真实密钥、输出及思考参数验证连接、流式和无副作用echo工具协议：必须返回正确工具名称/调用ID、可解析且正确的参数，收到对应tool结果后正确完成后续回答。只有连接/流式/工具均通过才写入；前端测试按钮不是门禁，客户端成功标记不能绕过此验证。复用同一测试实现，总超时60秒，取消沿原context传递，错误提示脱敏，不调用用户的知识库、联网或文档工具。保存按钮显示“验证并保存”及等待状态，避免重复提交。

验证失败（含网络/鉴权/限流、忽略工具、参数非法、工具结果回传失败）返回明确提示，旧记录保持原状。修改部署身份仍需完整重新确认；改密钥、能力或重新启用会重新验证。仅停用旧系统模型允许跳过上游实测，避免故障模型无法停用；停用不改变能力配置。

此次短协议验证只证明当前部署和配置在该次请求中支持工具，不认证最大窗口，也不保证未来网络、配额或所有工具组合永久可用；最终输入预算、权限及运行时错误处理继续保留。没有新增持久化“测试成功”标记，因此旧记录的ready仍只表示静态配置完整，不能解读为历史实测凭证。
