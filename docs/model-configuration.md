# 模型配置与执行策略

## 用户配置边界

普通用户填写服务地址、模型ID、API Key后，仅调整上下文窗口和思考模式。API Key编辑回填原文并支持小眼睛；系统通用列表仍脱敏。当前仅支持OpenAI兼容文本接口。

思考开关根据服务端资料显示：none禁用，always锁定开启，optional且识别thinking/enable_thinking协议才允许切换；unknown或协议未知时禁用并显示沿用服务商默认。optional的新配置不猜厂商默认开关；用户可明确开启/关闭，或恢复默认。模式改变需重新验证完整工具调用；不把深度/快速模式当成厂商思考开关。

普通用户请求只提交reasoning_mode，服务端忽略其能力/额度/协议声明。服务端优先保留同身份旧配置，否则使用启用的系统模型中地址和模型ID完全匹配的部署资料；再读取当前部署/models明确额度或核实官方目录。代理不继承同名原厂资料。缺少最大输出资料时提示管理员补充，不虚构额度。

管理员页面默认同样只有窗口与思考；折叠“管理员部署资料”可补最大输出、独立输入限制、思考能力及协议、输出参数字段。来源用于资料记录，不代替工具实测。用户可选择较小窗口作为输入预算，模型最大输出能力不因此改写，实际输出仍受统一策略约束。

获取失败保留现有值；更换地址/模型身份会清空表单旧能力。修改窗口、密钥或思考设置会清除旧测试展示，请求期间切换身份、密钥或测试参数时旧结果不回填。用户编辑测试可传config_id，Controller传可信userID，Service按归属查询旧部署；不能通过其他用户配置ID读取能力或测试。

## 系统管理的调用参数

新建/更新配置统一保存 `execution_policy=managed_v1`。后端复制候选配置，移除用户提供的 `max_completion_tokens`、`temperature`、`timeout`、`reasoning_effort`，不能通过直接调用API绕过。既有显式不支持工具/思考冲突仍被拒绝。

实际基础输出额度由 `internal/llm/model_policy.go` 的统一策略决定：`min(8192, 模型最大输出, floor(总窗口/4))`。8192是本项目的请求策略上限，不是厂商最大输出默认值。缺失总窗口或最大输出仍拒绝。摘要等阶段仍可通过程序参数使用较小输出，最终序列化预算检查真实参数与模型上限。

温度不额外发送，沿用服务商行为；模型超时不由用户模型JSON覆盖，统一使用系统 `llm.timeout`（秒，默认120，环境变量 `LLM_TIMEOUT` 优先，必须大于0且可安全转换为Go时长）。每次模型调用从开始到全部输出结束均受限制；请求取消或更短的上游deadline仍提前生效。客户端缓存区分全部超时策略，各客户端共享Transport连接池，不修改共享HTTP Client。配置在启动时加载，修改后须重启服务。

流式额外使用 `llm.stream_first_output_timeout`（默认60秒，环境变量 `LLM_STREAM_FIRST_OUTPUT_TIMEOUT`）和 `llm.stream_idle_timeout`（默认30秒，环境变量 `LLM_STREAM_IDLE_TIMEOUT`），同样校验正整数和时长溢出。首输出从调用开始计时，包含建连及响应头等待；收到正文、思考或工具调用片段后，每个有效片段重新计算空闲时间，角色、usage及保活心跳不续期。持续输出仍受完整调用上限限制。TCP建连10秒、TLS握手5秒；移除共享Transport固定60秒响应头限制，非流式仅受完整调用上限与上游deadline约束，不套首输出/空闲规则。

该时限同样用于直接创建的模型验证客户端；验证流程既有60秒总时限仍有效。每次模型重试分别计时，当前尚未实现Agent总时限，因此 `llm.timeout` 不是整次聊天任务的总耗时上限。有部分输出后失败不自动重试，已有正文保留并标记“回答已中断，内容不完整”，发送错误终态；失败记录保存到历史。消费方提前退出时需取消调用context并关闭流（Eino当前流Close本身不能立即取消阻塞中的HTTP读取），聊天Runner退出时统一取消其运行context。前端等待15秒后显示“仍在处理”，45秒后显示继续等待/停止提示；180秒连续没有网络数据是前端断流兜底，重试进度事件可以续期，不表示模型调用上限为180秒。

保留原有规划、工具域、权限、审批、调用次数和摘要治理。不同模型本身仍会影响规划质量，短协议测试不是复杂任务效果认证。

## 保存与工具验证

用户无需勾选支持工具。后端补入的是产品要求，非厂商能力认定；配置真正可保存前仍以候选部署/密钥验证连接、流式、echo工具调用名称/ID/参数，以及tool结果回传后的回答。失败或取消不写入，旧记录保持不变；仅停用系统模型可跳过上游验证。

两类模型共享实现，总验证时限60秒，不调用用户实际业务工具。不接受客户端测试成功标记。新配置思考能力未知时按服务商行为验证，不能人工开启/关闭；已有明确不兼容的配置仍拒绝。最大窗口依赖额度资料，不用短请求证明。运行时仍检查最终消息、工具定义、实际输出和独立输入上限。

更换模型ID、地址或协议，服务端要求同时确认新窗口并取得新部署资料，传 `reconfirm_capabilities=true`，否则拒绝保存。界面获取结果会核对请求时的部署身份，防止旧结果回填。

## 数据库升级与兼容

沿用 `models.config` 和 `user_model_configs.config` JSONB，本轮思考四态复用JSONB无需新增列或删除旧记录；既有准确协议/模式保留。旧库先执行 `scripts/migrations/20261013_model_limits.sql` 去除窗口默认，再执行 `scripts/migrations/20261014_model_managed_policy.sql`。

20261014升级事务仅去除旧执行字段并写入managed_v1，不修改窗口、最大输出、输入限制、工具声明、地址、密钥和思考兼容开关；可重复执行。未知能力仍为待确认，不新增旧记录的工具认证。新库初始化schema不含窗口默认，模型由Service创建并验证。

升级前备份配置，升级后核对记录数与所有非config字段、协议保留和重复执行一致性。当前数据库本轮已备份并升级：系统模型1条、用户模型1条；均静态配置完整。静态完整不代表本轮真实服务商工具实测成功。

废弃温度、模型独立超时及思考强度的LLM结构、校验和发送分支已删除；底层拒绝这些旧字段，已有库必须先执行升级。Service接收旧客户端参数时先清理，不保存或执行。本轮没有删除有效checkpoint或恢复路径。执行策略版本进入持久配置及客户端缓存key。升级或替换模型配置会改变运行预算，进行中的旧checkpoint按现有配置一致性检查处理，必要时新建运行。

## 验证

`SOLVIFY_MODEL_CONFIG_DB_TEST=1 go test -vet=off -p 1 ./scripts/migrations` 在隔离schema验证两个SQL升级和重复执行；普通CI不连接真实数据库。共享Service模拟真实HTTP协议覆盖简化配置保存、工具失败零写入、候选密钥、取消及停用。LLM验证系统输出预算与旧执行参数隔离；前端验证简化表单完整性和build。

后端进程需要重新加载代码。数据库升级不意味着运行中的二进制已更新。真实供应商可用性和复杂任务效果与离线门禁分开验收。

本轮增加模式与工具冲突、未知思考禁止切换、用户伪造能力无效、部署精确匹配和编辑测试归属验证。获取连接失败不宣称模型不支持工具；当前模式测试失败不会自动改模式保存。
