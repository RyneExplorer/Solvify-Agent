# 上下文管理迭代计划

日期：2026-10-12。状态：P0—P3 实现及 P4 观测/离线评估入口已交付；真实效果调优待用户验收。
需求基线：[上下文管理迭代需求](context-management-requirements.md)。

## 1. 方案与边界

共用一个 ContextService、一套预算计算和最终模型保护；快速、深度各角色与专业任务分别管理运行输入、轨迹和摘要。复用 PlanExecute、budgetGuard、budgetModel、会话摘要及数据库 checkpoint。

Service 负责权限、素材及 Request 转换；Agent 负责角色输入、完整组和运行状态；internal/llm 负责同源预算与最终调用保护；Repository 持久化必要数据。Controller 不增加上下文业务逻辑。

保留路由/DTO/SSE，预算错误映射现有业务错误与聊天终态。公开契约变化独立评估，不建设通用上下文框架或两个空壳 ContextService。已实施基线、P0/P1 与独立进程 checkpoint 验证，具体证据和验收边界见 [迭代记录](../tasks/context-iteration-report.md)。

P2/P3 数据库升级、运行策略、恢复兼容和工程验证命令见 [运行迭代实施说明](context-runtime-implementation.md)。

## 2. 改动前基线与缺口

已有快速 Handler、深度 Generate/Stream/WithTools 包装及专业任务压缩；工具占满时已返回零额度。重点是强化保护而非重新建设。

工具占满时实际返回 (0,0,0)，问题在下游默认回填。budgetModel 复用 budgetGuard 算法；快速持久状态与深度调用副本职责不同。深度指令已作为 system 消息被 messagesTokens 统计，instruction 空串不构成漏计证据；应验证最终消息而非仅查看 instrTokens 日志。

仍需解决超限放行、输出预留不同源、零额度回填、召回排序/超长候选、累计轨迹增长、Replanner 结果重复、运行版本一致性。已有深度 Request 状态先核对冻结覆盖范围。

## 3. 统一预算（R01）

使用 GetEffectiveMaxContextLength 与 pkg/tokenutil：

```text
L = 有效模型窗口
O = 本次实际生效最大输出 token
M = 同源算法计算的估算裕量
C = L - O - M                    输入硬上限
U = 最终消息 + 实际工具定义估算
S = floor(C × softRatio)          压缩水位
T = floor(C × targetRatio)        压缩目标
```

指令在最终消息中只计一次，不以首条 system 猜测去重；工具计入 U，不从 C 再扣。覆盖正文、角色开销、工具名称/参数/id、配对字段/schema。分区额度从 C 扣除实际固定内容计算，最终仍核对完整 U。

初始 softRatio=0.80、targetRatio=0.70，满足 0<targetRatio<softRatio<1。不同模式可调整软策略，硬规则一致；裕量算法须明确且可测试，依据 usage 校准，不承诺数学保证。

配置唯一来源定为 pkg/config 的上下文策略配置：快速/深度分别配置软水位和目标，默认值只在配置默认初始化处定义，internal/llm 消费解析结果，不在 Agent 再放常量。上述 0.80/0.70 为待实测候选，不直接覆盖现有 0.60/0.75；基线与对比完成后确定上线值。裕量参数同源，实际输出选项仍以本次请求为准。

先解析客户端默认、调用级及供应商扩展输出选项，取得实际 O，同步预算与请求；统一默认来源，核对推理模型输出语义。未知窗口用注册信息，仍不可确定则配置错误。

最终包装器覆盖 Generate/Stream/WithTools 和调用级覆盖，WithTools 返回新实例。预算基础不依赖 Agent。budgetModel 保留薄适配或迁入 llm，选定后只留一个最终检查实现；快速 Handler 负责持久压缩，最终保护核对实际输入，避免重复扣额/重复有损处理。

超 S 有限压缩；未达 T 但 U<=C 可调用；U>C 或必要内容本身超限返回业务错误。摘要/记忆也采用受限边界，不经过递归运行压缩。

先降级后拒绝：删除允许减少的可选素材并重计，预算内回答；必要内容仍超限才报错。上线前需明确可删除范围、降级提示和失败后的用户操作，这是产品行为验收项。当前放行也可能被供应商拒绝，不能用“至少能得到回答”作基线。不得提供确认超硬预算仍调用的兜底。

## 4. 会话装配与召回（R02）

显式区分未配置与零预算，调整最小字段及全部调用方。核对 RetrievalBudget 消费者，删除确认未使用的传递。

按实际模式指令、工具和问题估算后选素材，角色装配完成再计数。画像/偏好/摘要/记忆有限额，当前问题不能作为历史被静默裁剪。

召回顺序：权限确认→保留向量距离升序→按 ID 去重保留排名→按两路排名融合→预算内选候选→跨容器去重/剔除本轮→按时间组织并标来源。关键词排名按真实实现解释，不直接混合距离和关键词原值；融合参数固定后样本验证。

超长项跳过继续，关联问答/包装计入预算。65%近期/35%召回为起点，无召回额度可让给近期。知识库继续通过工具进入，不重复检索。素材加载受超时限制，向量查询等待 embedding，可选召回失败可降级。

候选按距离/融合排名及 ID 保持全序，选中内容按时间及 ID 展示；对应 order_guard_test.go 规则，不要求所有阶段都按时间排序。

## 5. 模式与角色治理（R03、R04）

快速：保留 quick_agent.go 独立流程，通过 BeforeModelRewriteState 发布持久压缩；优先可选召回/旧结果，短请求不强制摘要，保持澄清恢复链路。

深度：plan_execute_builder.go 的 GenInputFn 选择角色输入；plan_execute_task.go 管专业任务独立状态。Planner 取目标/约束/能力，Executor 取批次/状态，专业 Agent 取任务/依赖，Replanner 取有限结果/状态，汇总取结论/证据。

提前治理 Results/ExecutedSteps 重复正文，采用输入投影，不删持久事实；保留计划版本、终态、依赖、拒绝和汇总覆盖。原文存储未上线时不生成假 artifactID，必要结果放不下明确失败。

核对 execute.go 的 PlanExecute、resumeLegacyDeepOrchestrator、runAgent，以及纠错/重试调用。模型包装只能处理调用副本或拒绝，不代表更新 checkpoint；持久状态在 Handler/运行边界发布。

## 6. 完整组与原文存储（R05、R06）

一个 assistant 与全部工具结果作为完整组，普通已完成用户回合作为另一类组；活动调用/审批/必要状态保留。

有限流程：减少可选旧召回→外置大结果→缩减旧完整结果→摘要旧组→淘汰已覆盖且具有必要恢复来源的组。每步重计，无进展则结束/换措施。

使用现有数据库，最小产物实体包含 owner/session/run/agent/task、toolCallID、内容/关键字段、哈希和创建/到期时间；新增规范 Repository 接口/实现与迁移。配置单产物/运行/用户限额。

产物原文保存后不可变，是原文唯一权威来源；消息展示是携带版本/哈希的派生内容，不回写原文。任务终态、审批与副作用仍以结构化执行记录为准。用户后续授权全部实现，P2 仍独立验证，但已纳入本轮交付。

保存成功后才替换模型可见正文，失败保留原文；引用保留真实成功/失败/拒绝与证据。受限读取工具检查当前权限、限制范围/输出，标明片段来源，避免反复外置。synthesis_review 当前无工具，不为读取直接扩大权限，由输入装配提供必要证据。

产物清理不得破坏有效 checkpoint。外置上线同时交付最小引用恢复一致性，不能将引用安全全部推迟到摘要阶段。

## 7. 摘要与恢复（R07、R08）

会话摘要/记忆保持后台职责；运行摘要按 run/agent/task 存储范围与哈希，不替换 Plan/Results/审批。摘要独立输入/输出/超时，按完整组处理，仅标记实际覆盖内容。

实施前核对 Eino v0.9.14 和实际模型扩展的 state/session/checkpoint 序列化契约，先复用已有深度 Request；不能仅修改 Message.Extra 就认为可跨进程保存。

若无合适扩展位置，新增最小运行快照及版本引用，checkpoint/快照/引用事务或原子发布。冻结原会话素材和工具标识，记录模型策略；恢复重新授权、重校验模型变化，时间更新单独声明。旧 checkpoint 安全兼容或明确拒绝，不自动重跑副作用。

锁外摘要不可变快照，发布前核对源版本，过时结果丢弃；完整状态一次发布。源丢失明确失败，审批继续走 ResumeParams。

## 9. 变更范围与验证

预期范围：internal/llm 与 pkg/tokenutil；Service 的 chat_budget/context_interface/context_service、聊天装配和恢复；Agent 的 budget_guard/budget_model/quick_agent、plan_execute_builder/task/model/runtime、execute/遗留恢复；必要 Entity/Repository/checkpoint store/tool/scripts，以及按需错误与配置。

不机械拆空壳抽象。新增业务接口按项目命名规范，Controller/Service 依赖接口。前端仅在已有错误呈现不足时调整，公开契约变化另行评估。

各阶段 Go 修改覆盖全量测试，本机按已记录资源约束使用 go test -vet=off -p 1 -count=1 ./...，以后台任务运行，日志与进程退出码判断结果，不用管道替代退出码；异步等待期间持续报告进度。关闭测试内 vet 后另行运行 go vet -p 1 ./...，若受资源阻塞明确记录未完成检查。

并行/恢复增加相关 race，迁移用临时库验证初建/升级，前端改动跑对应测试/构建。模拟模型证明预算、协议及确定性恢复；真实模型测质量/计数偏差/工具闭环，证据分别记录。路由改变按 AGENTS.md 补行为测试。

已有文件保持原行尾；新增 Go 文件统一 LF，不混用 CRLF/LF。gofmt 后检查字节与 diff，避免格式化将已有 CRLF 整文件改写。排序修改运行 repository 的 order_guard_test.go 行为检查，相关度选择与时间展示各自保持全序。

完成前检查限定 diff、职责/依赖方向/耦合及验证成本，保留用户已有修改。

## 10. 风险与复盘

P0 可能增加明确拒绝，长任务完成率提升需 P2/P3。P1 优先减少重复和无用内容。外置增加存储/读取，摘要增加耗时和模型费用；实测后调整，不承诺收益百分比。

框架契约、旧 checkpoint、配置变化及源生命周期不符合预期时，更新计划后实现。每阶段在 tasks/todo.md 记录验证、未覆盖项与复盘，文档勾选不能代替行为证据。
