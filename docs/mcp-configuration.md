# MCP配置

开发约束见[AGENTS.md](../AGENTS.md)。用户配置入口为「设置 → MCP」，管理员入口为「后台管理 → MCP预置」。普通HTTP工具配置和旧用户工具接口已经移除。用户可管理MCP连接与其提供工具的启停，不单独创建工具或配置工具供应商。

## 连接方式

- **系统预置**：管理员维护固定MCP地址、Headers模板和用户配置字段；用户选择预置并填写字段，例如API Key。预置可以指向第三方服务，不要求本项目实现服务。每个用户对同一预置保留一个绑定。
- **自定义HTTP MCP**：用户填写公网Streamable HTTP端点，选择无认证、Bearer Token或API Key请求头，也可填写额外Headers。连接和调用时限可选。
- 系统预置还支持已有SSE服务。当前不支持stdio、OAuth授权流程、用户自定义URL模板或凭据自动刷新。

「测试连接」使用表单当前配置执行初始化与工具发现，只展示工具清单，不调用tools/call。保存配置只做本地校验；服务是否在线、凭据是否有效以连接测试及实际调用为准。用户不会单独配置或试运行某个工具。

## 用户连接与工具启停

设置页按「系统 MCP」和「自定义 MCP」分组。系统来源包含管理员创建及部署YAML同步的预置绑定；用户只修改本人的凭据和开关。自定义来源是用户自行填写的HTTP端点。连接列表显示来源、预置名称、本人启用状态与当前有效状态，不返回Headers或凭据。

每个连接都有总开关，展开「工具列表」后按需发现工具并展示名称、说明和逐工具开关。工具默认启用；停用偏好复用本人连接的 `config.disabled_tools` 持久化。连接停用后全部工具不可调用，但仍可查看工具与调整偏好；再次启用连接保留原选择。编辑凭据不会清空工具偏好。启用工具时校验远端当前确实提供该工具，停用无需远端在线；管理员停用预置后不能重新启用工具或连接。

总开关及工具开关控制本应用的调用资格，不远程启动或终止第三方MCP进程。停用后阻止后续调用，并在已有工具实例实际执行前重新校验；已发出的外部请求不会因此撤回。聊天仍需在深度模式选择有效连接。工具开关按单个名称原子更新，保留凭据和其他工具偏好；并发的过期连接编辑会提示刷新重试。

## 联网搜索与API Key

联网搜索由提供搜索能力的MCP实现。本项目不再直接调用Tavily、Brave等搜索HTTP API，也不再读取 `tools.web_search`。搜索MCP的地址、认证方式和Key种类应以服务商接入说明为准，搜索API Key不一定就是远程MCP的认证Token。

### Exa官方免费搜索预置

Exa维护的[官方MCP服务与接入说明](https://github.com/exa-labs/exa-mcp-server#authentication)支持有限额的匿名访问，无需API Key。匿名限额由服务商调整，官方说明未承诺固定免费次数；被限流时需稍后重试，或按官方方案申请认证。本预置不启用需要认证的Exa Agent能力。

将以下条目添加到部署配置 `tools.mcp_servers`，启动时同步为系统预置。已有运行环境也可由管理员在MCP预置中填写相同连接，无需重启；不要重复添加同一服务。

```yaml
- name: "exa-search"
  description: "Exa 官方联网搜索：搜索网页并读取正文；免 API Key，有匿名用量限制"
  transport: "http"
  url: "https://mcp.exa.ai/mcp?tools=web_search_exa,web_fetch_exa"
  config_schema:
    type: object
    properties: {}
  connect_timeout: 30
  call_timeout: 90
```

在「设置 → MCP」中添加 `exa-search` 预置，无需填写凭据；随后在深度模式输入框选择该连接。系统预置不会自动为所有用户创建连接或绕过对话选择。

该端点显式选择两个工具，工具定义由服务商发现接口提供：`web_search_exa`搜索网页并返回来源与摘要；`web_fetch_exa`读取指定URL的正文，支持多个URL。它们分别对应search和fetch，但MCP协议不要求工具必须使用这两个名称，也不要求每个服务只能有两个工具。2026-10-19使用本项目客户端匿名实测工具发现、Go官方发布说明搜索与正文读取成功；具体工具参数以运行时schema为准。

### 需要API Key的搜索服务

若远程MCP要求请求头 `Authorization: Bearer <key>`，管理员可添加如下预置：

```yaml
tools:
  mcp_servers:
    - name: "search"
      description: "搜索服务；按实际服务商说明获取凭据"
      transport: "http"
      url: "https://search.example.com/mcp"
      headers:
        Authorization: "Bearer {{api_key}}"
      config_schema:
        type: object
        properties:
          api_key:
            type: string
            title: API Key
            secret: true
        required: [api_key]
      connect_timeout: 30
      call_timeout: 300
```

以上地址仅为占位示例，需要替换为真实MCP端点。也可在管理页录入相同内容。用户只填写自己的API Key，服务端解析到当前用户的认证头，并在initialize、tools/list和tools/call中发送；凭据不作为模型工具参数。若服务要求 `X-API-Key`，改为该请求头；若搜索凭据由远程MCP服务在其部署环境中管理，用户应填写该MCP要求的连接凭据，而非把搜索Key任意塞进工具参数。

配置字段支持string、number、integer、boolean，校验required、类型及字符串enum；不是完整JSON Schema校验器。用户字段只可绑定Headers，不能改写预置URL。部署预置从YAML同步；后台预置直接保存数据库，无需重启。部署预置在后台仅开放超时编辑和启停；重启保留管理员超时及停用状态。

## 使用范围与隔离

快速模式不连接MCP；深度模式可以在输入框选择已启用的MCP连接，空选择明确不使用。PlanExecute主流程仅规划和委派，实际外部能力进入web_research专业子Agent。角色名沿用已有实现，但是否能联网搜索取决于已连接MCP的真实工具；普通数据库、文件等MCP不会自动具备搜索能力。内部知识检索、文档管理及澄清能力继续由系统管理。

连接池按用户、连接ID及有效配置隔离，避免相同端点或相同Key串用会话。每次实际调用前重查归属、连接启用状态、模板状态和有效配置；删除、停用或轮换凭据会阻止旧工具实例继续调用。配置变化后需要重新发起任务；已经发送的外部请求无法因此撤回。审批、取消和原有checkpoint规则继续生效；历史有效MCP的配置ID及工具名前缀在迁移后保留，恢复时仍校验最新配置。

个人HTTP连接只允许服务器可访问的公网地址：每次拨号检查全部解析结果并固定目标IP，禁用环境代理、重定向和跨源请求，防止访问内网或转发凭据。管理员预置是受信任的部署入口，可连接企业内网。单个响应体上限8MiB，服务工具数上限128，请求配置对象各不超过64KB，MCP用户接口请求体上限256KiB。

通用列表不返回配置和Headers；只有本人详情用于编辑时回读原值，关闭编辑框清理本地表单。当前凭据随配置保存在数据库JSONB中，未增加应用层加密；数据库与备份的访问控制由部署方管理。连接测试错误对用户返回脱敏提示。

## API与升级

用户接口统一为 `/api/v1/user/mcp-connections`，使用现有登录鉴权：

- GET/POST集合：列出本人连接、创建。
- GET/PUT/DELETE `/:id`：读取本人编辑详情、修改、删除。
- GET `/:id/tools`：按需发现本人连接的工具，返回工具说明、偏好开关及有效状态，不执行工具。
- PUT `/:id/tools`：提交 `name` 与 `is_enabled`，原子保存单个工具开关；没有独立工具配置或执行接口。
- GET `/templates`：列出当前可用预置及用户字段，不返回预置Headers或共享凭据。
- POST `/probe`：探测当前草稿，或传本人连接ID；只初始化和发现工具。

管理员统一使用 `/api/v1/admin/mcp-templates`：GET列表、POST创建、GET/PUT/DELETE `/:id`，以及POST `/probe`。模板直接保存 `key`、名称、`connection` 与 `config_schema`，没有工具类型、供应商类型或配置包装层。列表不返回连接凭据，管理员编辑详情才返回连接。原 `tool-types`、`provider-types`、`mcp-servers`、`tools/test` 及用户工具路径返回404。

新数据库执行 `scripts/init_knowledge_schema.sql`。已有库按顺序执行 `scripts/migrations/20261017_mcp_connections.sql`（尚未升级用户连接时）与 `scripts/migrations/20261019_mcp_templates.sql`，步骤见[开发指南](DEVELOPMENT.md)。迁移保留旧MCP配置ID，只迁移mcp类型，不迁移普通HTTP工具；第二步将旧MCP预置迁入 `mcp_templates`，保留ID、认证模板、字段schema、启停、时限与原工具名前缀，并把用户绑定外键改指新表。旧类型停用会物化为模板停用；不同旧类型的同名供应商采用独立迁移标识。旧表仅保留为升级历史，运行时不再读取，也不再保留对应Entity、Repository、Service和注册表。脚本有版本标记，重复执行不覆盖编辑，也不会复活已删除连接。同一用户对同一预置的历史重复绑定需在首次迁移前核对，唯一索引冲突时事务整体回滚。

离线验证包括本地MCP SDK认证链路、用户隔离、凭据轮换、网络边界、临时PostgreSQL schema重复迁移及独立进程读回。真实联调结果见下节。
