# 钉钉授权码重复兑换修复设计

## 问题

钉钉扫码成功回调可能重复触发。第一次授权码兑换成功并写入绑定后，后续回调再次兑换一次性授权码，导致钉钉 token 接口返回 400，但绑定结果已经成功。

数据库查重时出现的 `record not found` 表示解绑后尚无对应 unionId 绑定，Repository 已将其作为正常未绑定状态处理，不属于本次错误。

## 方案

- 配置页和知识库同步弹窗分别增加授权码兑换中的状态锁
- 兑换请求进行中时忽略后续扫码回调
- 已经绑定成功时忽略后续扫码回调
- 请求失败后释放状态锁，用户可刷新二维码重新授权
- 不修改后端接口和数据库逻辑

## 验证

- 同一入口连续触发扫码成功回调时只发送一次兑换请求
- 绑定成功后不再展示后续重复回调的 400 错误
- 兑换失败后仍可刷新二维码重试
- 配置页和知识库同步弹窗行为一致
- 前端生产构建通过
